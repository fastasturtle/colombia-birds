# eBird: наблюдения Ани в туре

Входы шага `observations` (`pipeline/steps/build_observations.py`) из двух источников:

1. **Выгрузка** (вручную): `uv run python run.py observations --import <MyEBirdData.csv>` из личной выгрузки eBird Ани
   («Download my data»). Самый полный источник: протокол, длительность, комментарии, коды гнездования, номера медиа.
2. **Отчёт поездки eBird** (автоматически): шаг `ebird_trip` (`pipeline/steps/fetch_ebird_trip.py`) каждые 2 часа в
   `.github/workflows/observations.yml` забирает чеклисты Ани из публичного Trip Report группы. С ключом
   `EBIRD_API_KEY` — полные чеклисты через eBird API, без ключа — только виды и численность (без протокола и
   комментариев).

| Файл | Кто пишет | Что |
|---|---|---|
| `colombia_2026.csv` | `observations --import` | строки выгрузки с `State/Province` `CO-*` и датой не раньше начала тура (первая дата `data/itinerary.json`), все столбцы, тот же заголовок |
| `life_list_before_trip.json` | `observations --import` | `{before, exported, species}`: научные названия видов, отмеченных где угодно до начала тура (для «новый вид для Ани»), без координат и дат |
| `trip_reports.json` | вручную | `{user_id, reports: [{id, note}]}`: чьи чеклисты брать (eBird user id Ани) и какие отчёты; один отчёт покрывает не больше 31 дня, поэтому список |
| `trip_report.csv` | `ebird_trip` | чеклисты Ани из отчёта(ов) в формате выгрузки (тот же заголовок); пустые столбцы — то, чего источник не даёт |
| `trip_report_state.json` | `ebird_trip` | состояние для инкрементальных запросов (чеклисты и их `numSpecies`, счётчики таксонов, загруженные строки, имена кодов не из базы) и `fetched_at` — время последнего запуска, который что-то изменил; из него CSV пересобирается каждый запуск |

**Кто главнее.** Для одного и того же `Submission ID` берутся строки выгрузки, отчёт добавляет только чеклисты, которых
в выгрузке ещё нет. Чеклист отчёта с другим id, но той же датой, временем и локацией, что у чеклиста выгрузки
(чеклист удалили и ввели заново), считается повтором и пропускается (виден в `data/sources/observations_report.md`).
Пять чеклистов Ани за 1–2 октября раньше периода отчёта (с 3 октября) и есть только в выгрузке.
После нового `--import` ничего делать не надо: чеклисты, которые есть только в отчёте, снова попадают в данные при
следующем запуске `observations` (в том числе плановом).

Полная выгрузка (вся история наблюдений по миру с местами и датами) — личные данные: в репозиторий не попадает,
держать вне его. Руками файлы, кроме `trip_reports.json`, не править: новая выгрузка → повторить `--import`;
отчёт → `uv run python run.py ebird_trip observations` или Actions → observations → Run workflow.
