| 18 | Вероятность и «интересные» (27.09) | Для каждой пары (вид, место) три состояния только по осенней (сен–ноя) частоте GBIF в радиусе локации: «Точно увидим» (`sure`, ≥ 1 % осенних записей птиц), «Возможно» (`maybe`, 0,1–1 %), «Вряд ли» (`unlikely`, < 0,1 %, < 3 осенних записей или вида нет в списке GBIF локации). Пороги — константы в `pipeline/common.py`. Для дня — лучшее состояние по локациям дня, для списка без места — лучшее по всем локациям маршрута. «Интересная» (★, бывшая «изюминка») — цель из отчётов о поездках для этой локации, эндемик или почти-эндемик Колумбии (`near_endemic` в `species_index.json`, нет поля = false) или вид с узким ареалом; от состояния не зависит, цели из отчётов не выкидываются (без записей GBIF — «вряд ли» + ★). На всех списках (дни, локации, семейства, «Все виды») один фильтр из двух переключателей: «Точно · Точно и возможно · Все» (по умолчанию «Все», с 06.10; до этого «Точно и возможно») и «Все · Интересные · Почти-эндемики · Эндемики» (по умолчанию «Все»); уровни вложены: Эндемики ⊂ Почти-эндемики (почти-эндемики и эндемики) ⊂ Интересные (★) ⊂ Все. С 07.10 выбор живёт в адресе страницы (`lv=sure|maybe`, `tag=int|nend|end`, по умолчанию параметра нет) рядом с поиском, семействами, местами, высотой и признаками (`q`, `fam`, `site`, `elev`, `t`; на странице семейства у списка по дням префикс `d-`), так что ссылка и перезагрузка воспроизводят вид. Каждая страница помнит свои фильтры отдельно: при каждом изменении параметры фильтра из адреса сохраняются в `localStorage` под ключом `cb.f:<путь без base>` (в состоянии по умолчанию ключ удаляется); страница, открытая без параметров фильтра, восстанавливает их и вписывает в адрес (`replaceState`), а параметры в адресе (общая ссылка) побеждают и перезаписывают сохранённое. Восстановление делает и встроенный скрипт `FilterScope.astro`, так что статичные страницы (день, локация, семейство) с первой отрисовки показывают отфильтрованный список. Другие страницы не затронуты и открываются с «Все» + «Все». Раскрытость панели фильтров и «Признаков» тоже запоминается по странице (`cb.fp:<путь>`, на странице с двумя списками ещё `#d`); `?panel=traits` / `?panel=1` раскрывают их вместо сохранённого (параметр `panel` не фильтр и не сохраняется). Прежние общие ключи `localStorage` (`cb.filter`, `cb.filter2`, `cb.filter.open`, `cb.filter.traits`, точные имена, новые ключи не задевают) удаляются при загрузке; до 07.10 выбор был общим для сайта через `cb.filter2`. Счётчики на страницах и в фасетах определителя считаются под текущий фильтр, карточки дней на главной — под фильтр по умолчанию (без JS). Значки на плитках и строках: ★ интересная, «энд.» эндемик, «п.-энд.» почти-эндемик (27.09, переключатель вместо «Только интересные»). |

| 20 | Офлайн (28.09) | Сайт статичный, офлайн — рукописный service worker без Workbox и без переключателя «офлайн-режим»: сеть либо есть, либо нет. HTML — сразу из кэша, обновление в фоне (в обход 10-минутного кэша GitHub Pages), свежесть сигналит плашка «Есть новая версия»; при обновлении страницы worker дотягивает её `_astro`-файлы, чтобы она работала и без сети. При открытии страницы, если worker в фоне положил в кэш копию с другой сборкой (сообщает странице `PAGE_REFRESHED`), а пользователь ещё не начал читать (не скроллил и не трогал экран, < 15 с с открытия, не идёт скачивание пакета, не `/offline/`), страница перезагружается сама один раз; иначе плашка «Есть новая версия» (решение владельца 29.09); от зацикливания — метка версии в `sessionStorage` (`cb.autoreload`): для одной версии не больше одной автоперезагрузки за вкладку. Так с 28.09: раньше было «сначала сеть, таймаут 3 с», и приложение с экрана «Домой» 2–3 с открывалось чёрным экраном. Ничего тяжёлого не качается без явной кнопки: при обычном просмотре кэшируется только открытое и сама страница «Офлайн». Пакет (кнопка на `/offline/`) = все страницы + `_astro` + миниатюры и средние фото (≈ 430 МБ), крупных фото нет (без сети подменяются средними). Качает страница, не worker: 6 потоков, прогресс всегда пересчитывается по содержимому кэша, поэтому остановка и закрытие вкладки ничего не теряют. Версии: build id в `version.json`, `sw.js` и `<meta name="build-version">`; у файлов из dist — хэш содержимого, у фото — ключ (фото на R2 неизменяемы). Два кэша `cb-pages-v1`/`cb-media-v1` не зависят от сборки. Префикс `cb-` — потому что Cache Storage общий для всех проектов на fastasturtle.github.io: brazil-birding-layover держит `pages-v1`/`media-v1` и чистит их под свой манифест, стирая наши страницы (обнаружено 30.09/01.10); worker после активации в фоне переносит наши записи из старых общих кэшей (не задерживая открытие) и удаляет только свои `cb-*`. На iPhone пакет качать в приложении с экрана «Домой» (своё хранилище). Удаление — второе нажатие «Точно удалить?» вместо `confirm()`. CDN GitHub Pages держит `version.json` и страницы до 10 минут (`max-age=600`, `no-cache` и параметры в URL его не обходят), поэтому плашка «Есть новая версия» и фоновое обновление приходят с задержкой до 10 минут после деплоя; принято как есть 28.09 (альтернатива: класть `version.json` в R2 с `no-store`). |
